Segmento 1 · Grafos y ontología03 / 16

Un grafo de conocimiento no es una tabla ni un PDF

Nodos

Entidades del mundo: Austria, Wien, el Rin, el Danubio. Cada una tiene un IRI, no solo un nombre.

Aristas tipadas

Relaciones con semántica: capital, neighbor, locatedIn, length. No son “links” genéricos.

Preguntas estructurales

Se puede pedir “quién limita con X” o “ordená por población”. Eso no es buscar texto parecido.

La semántica viaja con el dato. Austria no es un párrafo: es un Country unido a una City por capital.

Segmento 1 · Grafos y ontología05 / 16

La ontología dice qué tipos de cosas existen

Clases que usa el agente

  • mon:Country — país
  • mon:City — ciudad (política y geográfica)
  • mon:Province — provincia / estado
  • mon:River, mon:Lake, mon:Sea — agua

Jerarquía (simplificada)

  • MondialThing es la raíz
  • PoliticalThing ∪ GeographicalThing
  • Water = River ⊎ Lake ⊎ Sea
  • Un río es también Line: por eso tiene length

Definida en data/mondial-meta.rdf con RDFS/OWL: owl:Class, rdfs:subClassOf, uniones disjuntas.

Segmento 1 · Grafos y ontología06 / 16

Las propiedades son el vocabulario de las preguntas

Object properties — unen entidades

  • mon:capital — Country → City (funcional)
  • mon:isCapitalOf — inversa
  • mon:neighbor — Country ↔ Country (simétrica)
  • mon:cityIn, mon:locatedIn, mon:flowsInto

Datatype properties — literales

  • mon:name — string (a menudo exónimo alemán)
  • mon:population, mon:area
  • mon:length — largo de un río
  • Sirven para ORDER BY y rankings

Detalle práctico: Mondial nombra Wien, Donau, Rhein. Si el SPARQL busca "Vienna" o "Danube", vuelve vacío.

Segmento 2 · RAG08 / 16

RAG: recuperar evidencia y recién después generar

RAG clásico de documentos

  • Partís texto en chunks
  • Embeddings + similitud
  • El LLM resume los pasajes
  • Sirve para manuales y PDFs

Este RAG

  • La base de referencia es el grafo
  • Recuperar = SELECT SPARQL
  • El LLM redacta en español con esas filas
  • Si el grafo calla, no se inventa la capital

Patrón: pregunta → recuperación (tool) → generación. El modelo no es la fuente; es el traductor a SPARQL y a español.

Segmento 2 · RAG10 / 16

Flujo de una pregunta

1. Prompt

Clases, propiedades, plantillas SPARQL y tabla de nombres Mondial. Regla: consultá antes de responder.

2. SELECT

El modelo escribe un SELECT que empieza con PREFIX mon:. Un triple = tres términos.

3. Tool

Normaliza el PREFIX, reescribe aliases (Alemania→Germany, Danubio→Donau) y ejecuta.

4. Respuesta

Hasta 50 filas. El modelo redacta en español solo con eso. Si hay cero filas, falla.

Una sola consulta SPARQL por pregunta. Si falla o viene vacía, la respuesta es que no hay dato en el grafo.

Segmento 2 · RAG11 / 16

Por qué SPARQL y no un embedding

Lo que SPARQL resuelve bien

  • Joins: países que neighbor a Alemania
  • Rankings: ORDER BY DESC(?pop)
  • Tipado: solo a mon:River
  • Cero hecho inventado si el grafo no trajo filas

El costo

  • El LLM tiene que escribir SPARQL válido
  • Los literales de name son frágiles
  • Por eso: plantillas y aliases de nombres
  • Debug: descomentar el print en graph.py
Segmento 3 · Queries de prueba12 / 16

«¿Cuál es la capital de Austria?»

PREFIX mon: <http://www.semwebtech.org/mondial/10/meta#>
SELECT ?cap WHERE {
  ?c a mon:Country ;
     mon:name "Austria" ;
     mon:capital ?city .
  ?city mon:name ?cap .
}

Qué tiene que pasar

El agente traduce la pregunta a un patrón Country → capital → name.

Fila del grafo: Wien.

Respuesta esperada en español: la capital de Austria es Viena (Wien en Mondial). El modelo no debería decir Vienna de memoria si la tool no corrió.

Segmento 3 · Queries de prueba13 / 16

«Nombrame 5 países que limitan con Alemania.»

PREFIX mon: <http://www.semwebtech.org/mondial/10/meta#>
SELECT ?name WHERE {
  ?c a mon:Country ; mon:name "Germany" .
  ?n mon:neighbor ?c ; mon:name ?name .
} LIMIT 5

El grafo tiene 9 vecinos

Netherlands, Belgium, Luxembourg, Czech Republic, Poland, France, Denmark, Austria, Switzerland.

Plantilla del prompt: usar solo mon:neighbor. No mezclar cityIn ni isCapitalOf.

La tool reescribe "Alemania" → "Germany" si el modelo se olvida de traducir.

Segmento 3 · Queries de prueba15 / 16

«¿Cuáles son los ríos más largos?»

PREFIX mon: <http://www.semwebtech.org/mondial/10/meta#>
SELECT ?name ?len WHERE {
  ?r a mon:River ;
     mon:name ?name ;
     mon:length ?len .
} ORDER BY DESC(?len) LIMIT 10

El grafo responde (km)

Lena 4400 · Irtysh 4248 · Yenissey 4092 · Ob 3650 · Volga 3531 · … · Donau 2845

Rusia entra en el recorte: aparecen ríos siberianos. El Danubio en Mondial se llama Donau. El prompt dice explícitamente: no busques un mon:name "longest".

Pregunta en español → SPARQL sobre el esquema → filas → frase. El grafo es la fuente; el LLM solo traduce.

Conclusiones · cómo mejorar16 / 16

El RAG funciona; el cuello de botella es el SPARQL

1 · Nombres y alcance

  • Usar othername / localname, no solo un diccionario de aliases
  • Filtro de continente: ríos «europeos» vía locatedIn, no todo lo de Rusia
  • Alinear literales con Wikidata o un léxico ES→Mondial

2 · Agente y consultas

  • Clasificar intención y rellenar plantillas, en vez de SPARQL libre
  • Inyectar el esquema al vuelo (clases/props), no un prompt fijo
  • Validar el SELECT contra la ontología antes de ejecutarlo

3 · Producto y evaluación

  • Mostrar el SPARQL y las filas en la UI
  • Set dorado de preguntas + métrica de acierto
  • Triplestore (Fuseki) si el grafo crece; memoria para follow-ups

Hoy el sistema demuestra el patrón. El siguiente paso es que falle menos al escribir la consulta y que se pueda auditar cada respuesta.
